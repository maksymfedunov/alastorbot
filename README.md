# AlastorBot

A Telegram bot with an AI character, **Alastor Rowley** — a crossroads
demon and dealmaker from an original book universe. The goal isn't a
clever architecture — it's a convincing, alive character: the user
shouldn't feel like they're talking to a bot.

## Project structure

alastorbot/
├── pyproject.toml # dependencies (Poetry)
├── alembic.ini # migrations config
├── .env.example # environment variable template
├── alastorbot/
│ ├── main.py # entry point, starts the aiohttp webhook server
│ ├── config.py # settings from .env (pydantic-settings)
│ ├── bot/
│ │ └── handlers.py # Telegram message handling (aiogram)
│ ├── database/
│ │ ├── models.py # SQLAlchemy models (User, Message, UserMemory)
│ │ ├── engine.py # SQLite connection
│ │ └── repositories.py # reads/writes, daily limit, history trimming
│ ├── character/
│ │ ├── persona.py # SYSTEM_PROMPT — canon, personality, speech style
│ │ └── ai_client.py # Gemini API calls + context assembly
│ ├── rag/
│ │ ├── chunking.py # splits the books into chunks
│ │ ├── embeddings.py # chunks -> vectors via the Gemini Embedding API
│ │ └── retriever.py # builds the FAISS index and searches it
│ └── memory/
│ └── memory_manager.py # parses [ЗАПОМНИТЬ: ...] markers out of replies
├── alembic/versions/ # database migrations
├── data/
  ├── books/ # source .docx books for RAG
  ├── chunks.jsonl # book chunks (generated by chunking.py)
  ├── vector_store/ # embeddings.npy, index.faiss, metadata.jsonl
  └── alastorbot.db # SQLite database (not in git)



## Setup

```bash
poetry install
cp .env.example .env
# fill in .env: BOT_TOKEN (from @BotFather), GEMINI_API_KEY
# (aistudio.google.com/apikey), WEBHOOK_BASE_URL, WEBHOOK_SECRET
```

## Preparing the lore (once, before the first run)

Place the books in `data/books/*.docx`, then:

```bash
poetry run python -m alastorbot.rag.chunking
poetry run python -m alastorbot.rag.embeddings
poetry run python -m alastorbot.rag.retriever
```

`embeddings.py` calls the Gemini Embedding API in batches, with
checkpointing and retry-with-backoff on rate limits — safe to
re-run if it gets interrupted partway through.

## Database

```bash
poetry run alembic upgrade head
```

## Running locally

The bot runs on a webhook (aiohttp server), not polling, so a local
run needs a publicly reachable HTTPS URL (e.g. via ngrok) pointed at
`WEBHOOK_BASE_URL` in `.env`. For quick local testing without a
public URL, temporarily switch `main.py` back to
`dp.start_polling(bot)`.

## Deployment

Deployed on [Render](https://render.com) (free tier):

- **Build Command:** `pip install poetry && poetry install --no-root`
- **Start Command:** `poetry run alembic upgrade head && poetry run python -m alastorbot.main`
- Environment variables: `BOT_TOKEN`, `GEMINI_API_KEY`, `DATABASE_URL`,
  `WEBHOOK_BASE_URL`, `WEBHOOK_SECRET`, `PORT`

The free tier's filesystem resets on every restart/redeploy/sleep
cycle, so:
- The RAG index (`data/vector_store/*`, `data/chunks.jsonl`) is
  committed to the repo instead of regenerated on startup
- The SQLite database is *not* persisted — user data resets on
  restarts (a deliberate tradeoff to stay on the free tier)

## Features

- Lives-in-character dialogue, no commands or menus — even `/start`
  is treated as an ordinary message
- RAG search over the book lore (FAISS + Gemini Embedding API)
- Short-term memory — the last 20 messages of the conversation
  (older ones are trimmed automatically)
- Long-term memory — the model marks important facts about the user
  with `[ЗАПОМНИТЬ: ...]`, which get saved to the database and pulled
  into every future conversation
- Daily limit — 10 messages per day per user
- Retries and in-character fallback replies on API failures
- "Typing..." indicator, handling of non-text/overly long messages

## Stack

Python 3.12+, Poetry, aiogram 3, SQLAlchemy 2 + Alembic + SQLite,
Google Gemini API (chat + embeddings), FAISS, aiohttp (webhook server).
